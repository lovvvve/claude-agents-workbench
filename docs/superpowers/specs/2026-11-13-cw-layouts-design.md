# cw 布局保存与按设备选择 —— 设计

日期：2026-11-13（2026-11-14 补充审阅结论）
状态：待确认

## 1. 背景与动机

cw 启动后是固定的左右 60/40：左边 `claude agents`（Agent View），右边一个跟随当前 attach session 目录的 shell。

用户实际使用时，每次启动后都会**根据手头的业务或所用的设备，再手动调整一遍布局**：拆出更多 pane，在里面跑不同的命令，调整大小比例。这个重复劳动就是本功能要省掉的。

用户的一个真实常用布局（外接显示器，iTerm2，316×72）：

```
┌──────────────────────────────────────────┬───────────────────────────┐
│ ① claude agents（Agent View）              │ ④ 跟随目录的 shell（cw 原有） │
│              左栏约 2/3 宽                  │                           │
├──────────────────────────────┬───────────┼───────────────────────────┤
│ ② top                        │ ③ zsh     │ ⑤ zsh                      │
│                              │           ├───────────────────────────┤
│                              │           │ ⑥ npm exec @deepseek-ai/dsh@next web │
└──────────────────────────────┴───────────┴───────────────────────────┘
```

对应的 tmux 布局串：
`2fab,316x71,0,0{208x71,0,0[208x52,0,0,0,208x18,0,53{163x18,0,53,2,44x18,164,53,4}],107x71,209,0[107x52,209,0,1,107x9,209,53,3,107x8,209,63,5]}`

用户使用的设备：Mac 上的 iTerm2（笔记本屏幕、外接显示器两种），Windows 上的 Windows Terminal。

## 2. 目标

1. 把当前调好的布局保存下来，起一个名字（`cw -s`）。
2. 敲 `cw` 时弹出布局列表，选一个，工作台就变成这个布局。
3. 不同设备各自记住上次选的布局，列表默认停在那一项，回车即可。
4. 工作台已经在运行时，`cw` 同样弹列表，**在同一个会话里就地改成**选中的布局，已有 pane 里的进程一个都不杀。

## 3. 非目标

- 不保存 pane 的工作目录：除 ④ 跟随 shell 外，附加 pane 一律在 `~` 启动（用户明确要求）。
- 不自动执行保存的命令（见反目标）。
- 不做“一个布局一个 tmux 会话”。这个方案讨论过，用户选择了单会话模式。
- 不做 GNU screen 版本（之前做过，已整体撤销）。
- 不提供布局的重命名、删除命令。布局就是文本文件，直接改文件或删文件（见 §8）。

## 4. 反目标（技术上实现了但仍算失败的情况）

- **自动执行了保存的命令**。恢复布局时，命令只填进对应 pane 的命令行，**等用户自己按回车**。这是用户的明确决定，原因是保存时可能误记下 `terraform apply`、`kubectl delete` 这类一次性命令。
- **切换布局时杀掉了用户 pane 里的进程**，包括正在用 vim 编辑文件、正在跑的 `dsh web` 等。
- **切换布局后 ④ 不再跟随目录**，或 ① Agent View 被重启。
- **没保存任何布局的用户体验变差**：只有内置布局时，`cw` 的行为应与现在一致（不弹列表）。
- 往运行中的 Agent View 发送文本（会真的派发一个后台 session，见 `docs/pitfalls.md` 第 15 条）。

## 5. 用户体验

### 5.1 命令行参数

| 参数 | 含义 | 与现状相比 |
|---|---|---|
| （无） | 弹布局列表 → 新建或就地重排 → 进入 | 新增列表 |
| `-s` | 保存当前布局，交互式输入名字 | **含义改变**：原来是“只打印状态”（用户决定） |
| `-i` | 只打印状态，不进入 | **新参数**，承接原 `-s`（用户决定） |
| `-n 名字` | 独立工作台 `cw-名字` | 不变 |
| `-r` | 重启左侧 Agent View | 不变 |
| `-k` | 关闭工作台 | 不变；“保留”窗口随会话一起关闭 |
| `-h` | 帮助 | 更新说明 |

README、`usage()`、`install.sh` 结尾的提示要同步改。

### 5.2 启动：`cw`

1. 列出可选布局：内置的“默认”（即现在的左右 60/40）加上所有已保存的布局。工作台已在运行时，额外列出一项 **“保持现状，直接进入”**（用户决定），并标出当前正在使用的是哪个布局。
2. **默认项** = 这台设备上次选过的布局（规则见 §6）；没有记录时用“默认”。
3. 用户按编号选择，直接回车选默认项。
4. 选定后：
   - 工作台没在运行 → 按该布局新建（§7.3）。
   - 工作台已在运行，选的是**另一个**布局 → 在原会话里就地重排成该布局（§7.4）。
   - 工作台已在运行，选的就是**当前**布局 → 只按当前终端尺寸重算比例：不挪 pane，不填命令（§7.5）。
   - 选“保持现状，直接进入” → 什么都不改，直接进入。
5. 记下“这台设备 → 这个布局”，然后进入工作台（tmux 外 `attach`，tmux 内 `switch-client`，与现在一致）。

列表的显示形式用编号列表（我的决定），不依赖 fzf 等额外工具。

**我的决定：**
- 没有任何已保存布局时，不弹列表，行为与现在完全一致。
- 没有终端（stdin 不是 tty）时不弹列表，直接用默认项。

### 5.3 保存：`cw -s`

1. 对象是工作台主窗口，也就是含 `@cw_role=left` 的那个窗口。可以在工作台里的任意 shell 里执行，也可以在 tmux 外执行；`-n` 指定工作台时同样适用。
2. 提示输入布局名。名字可以用中文（我的决定：布局名不再用作 tmux 会话名，没有字符限制，只禁止 `/` 和以 `.` 开头）。
3. 列出识别结果：每个附加 pane 的位置示意和识别到的命令（空 shell 显示为空），让用户确认；**我的决定**：允许在确认时逐个修改或清空命令文本。
4. 同名布局已存在时，询问是否覆盖。
5. 写入布局文件（§8）。

“识别到的命令”指 pane 当前前台进程组组长的完整命令行（`/proc/<tpgid>/cmdline`）。pane 停在 shell 提示符时视为空 shell。

## 6. 设备识别与默认项（我的方案，用户未反对）

设备特征 = **终端类型** + **终端尺寸（列×行）**。

- **终端类型**
  - 在 tmux 外启动：读 `LC_TERMINAL`。iTerm2 会经 SSH 带上 `LC_TERMINAL=iTerm2`（已在用户会话中确认），Windows Terminal 不带。
  - 在 tmux 内启动：shell 里的 `LC_TERMINAL` 是这个 shell 启动时的值，可能来自另一台设备，**不可信**。改用 `tmux display -p '#{client_termtype}'`，tmux 3.5 会主动询问终端，对用户的 iTerm2 返回 `iTerm2 3.7.7`。Windows Terminal 在这里返回什么**尚未验证**，实现时要确认；拿不到就归为“其他”。
  - 归一化为两类即可：`iTerm2`、`其他`。
- **终端尺寸**
  - tmux 外：`tput cols` / `tput lines`。
  - tmux 内：`#{client_width}x#{client_height}`（不能用 `tput`，那拿到的是 pane 尺寸）。
- **记录**：每次在列表中选定布局后，追加或更新一条“工作台名、终端类型、宽、高 → 布局名”的记录。按工作台（`-n`）分开记，避免 `cw` 和 `cw -n api` 互相覆盖默认项（我的决定，来自审阅）。
- **默认项**：同一终端类型的记录里，取尺寸最接近当前尺寸的那条。iTerm2 窗口大小略有变化也能对上；笔记本和外接屏的尺寸差别很大，不会混淆。

## 7. 布局的套用

### 7.1 布局模型

一个布局由两部分组成：

- **切分树与比例**：与 tmux 布局串结构相同（`{}` 左右切、`[]` 上下切），但尺寸**按比例**保存，不保存绝对列数和行数。
- **每个叶子 pane 的角色**：
  - `left`：① Agent View。每个布局有且只有一个。
  - `right`：④ 跟随 shell。每个布局有且只有一个。
  - 附加 pane：带一段命令文本（可以为空）。

“每个布局都有 ① ④”是我的假设，用户没有反对。①④ 在布局里的位置可以不同。内置“默认”布局 = `{left 60%, right 40%}`。

### 7.2 按比例套用（已实测的约束）

在 tmux 3.5a 上实测：把 316×71 的布局串直接用 `select-layout` 套到 200×50 的窗口，tmux **不会按比例缩放**，而是从右边、下边把多出的部分裁掉。右栏从约 1/3 被压到 49 列，右下两个 pane 只剩 2 行和 1 行。

所以套用时必须由 cw 自己按当前窗口尺寸算出每个 pane 的绝对尺寸，生成新的布局串（含 tmux 的 4 位校验和），再执行 `select-layout`。注意每条分隔线占 1 列或 1 行。窗口太小、某些 pane 会小于可用尺寸时，按比例尽量分配，不报错退出。具体阈值由实现者决定。

### 7.3 新建（工作台没在运行）

沿用现在的建会话逻辑（锁、`9>&-`、`@cw_role`、watcher 等全部保留），然后：

1. 按布局的 pane 数补齐 pane。① 跑 `claude agents; exec $SHELL`；④ 带 `CW_DIRFILE`；附加 pane 在 `~` 启动交互式 shell。
2. 调整 pane 顺序，让它和布局串里叶子的顺序一致，再按 §7.2 生成布局串并 `select-layout`。
3. 附加 pane 若有命令文本，**填进命令行，不回车**（§7.7）。

### 7.4 就地重排（工作台已在运行，单会话模式）

在同一个会话、同一个主窗口里改成目标布局，pane 只挪动、不杀死。

1. **① ④**：找 `@cw_role=left/right` 的 pane，原样复用。如果被关掉了，就新建补回来。**不能**沿用现有自愈逻辑里“认领第一个没有角色的 pane 当 ①”那一步，多 pane 布局下它会把 `top` 之类的 pane 误认成 Agent View（我的决定，来自审阅）。
2. **复用候选**：主窗口里的其余 pane，加上“保留”窗口里的 pane。
3. **有命令文本的槽位**：优先挑一个前台正在跑**同一命令**的候选 pane，进程不中断，也避免再起一个重复的（比如两个 `dsh web` 抢端口）。
4. **空 shell 槽位，以及没匹配上的命令槽位**：优先挑停在 shell 提示符的候选 pane；命令槽位拿到空 shell 后，把命令填进命令行。
5. **还缺的槽位**：新开 pane（在 `~`）。
6. **用不上的 pane**：挪进本会话里的“保留”窗口，窗口名暂定 `保留`（我的决定），进程照常运行。“保留”窗口里没有 pane 时可以不存在。
7. 用 `join-pane`、`break-pane`、`swap-pane` 等**移动** pane，按 §7.2 套用比例；最后把焦点放回 ①。

匹配规则的细节，比如同一命令有多个候选时选哪个、命令是否要完全一致，由实现者决定。原则是**宁可新开，也不挪错**。

补充（我的决定，来自审阅）：
- 等待用户在列表里选择时**不持有锁**。选定之后再加锁，执行建立或重排。
- 在工作台的某个 pane 里执行 `cw` 时，这个 pane 和其他 pane 一样参与匹配和挪动。它当时在跑 `cw`，不算停在提示符的空 shell。

### 7.5 同一布局：只重算比例（用户决定）

最常见的场景是 SSH 断了重进，或者换了一台设备，然后在列表里回车，选中的就是当前布局。这时完整重排会重置你手动拖过的比例，把你后来自己拆出的 pane 挪走，还会把已经退出的 `top` 再填一遍。所以这种情况只做一件事：按当前终端尺寸重新计算比例，然后 `select-layout`。

- “当前布局”记录在主窗口的窗口选项上，比如 `@cw_layout`。不用会话级选项，原因见 `docs/pitfalls.md` 第 4 条。新建、重排、保存时都更新这个选项；用户保存时，当前布局就变成刚存下的那个名字。
- 如果主窗口的 pane 数量或切分结构已经和这个布局对不上（用户后来又拆过 pane），就不重算，按“保持现状”处理，并提示一行“当前 pane 与布局 X 不一致，未调整；如需还原请在列表中重新选择”（我的决定）。

### 7.6 比例只在执行 `cw` 时套用（用户决定）

不挂 `client-resized`、`client-attached` 之类的 tmux 钩子。直接 `tmux attach`、把 iTerm2 窗口拖到另一块屏、多台设备同时 attach，这些情况下窗口尺寸变了，比例按 tmux 自己的方式变化（不按比例），cw 不干预。因为换设备时本来就会执行 `cw`，那一刻会修正比例。

多台设备同时 attach 的行为维持现状：`cw` 在 tmux 外仍用普通 `attach`，不踢掉其他客户端。

计算比例时用的尺寸，就是这次要进入工作台的那个客户端的尺寸：tmux 外取 `tput`，tmux 内取 `#{client_width}x#{client_height}`。如果有状态栏，要先减去状态栏占的行数。

### 7.7 “只填不执行”

附加 pane 是交互式 shell，用 `tmux send-keys -l` 把命令文本送进去，不发送 Enter。注意两点：

- shell 可能还没初始化完（zsh 在读 `.zshrc`），提前发的按键可能被吞掉或打乱。实现者需要确认 zsh 下不会丢字，必要时等到提示符出现再发。
- 不要用 `tmux split-window "命令"` 的方式执行：那是 `$SHELL -c`，非交互，不读 `.zshrc`，nvm 等方式装的 `npm`/`npx` 找不到。何况本需求本来就不自动执行。

## 8. 存储（我的决定，实现者可调整格式）

- 布局：`~/.config/cw/layouts/<名字>`，一个布局一个文本文件。内容要能直接手改，至少包括切分树与比例、每个叶子的角色、附加 pane 的命令文本。格式由实现者定，但要满足：人能看懂并编辑；命令文本里的空格、引号、`$` 原样保存。
- 设备记录：`~/.config/cw/devices`（或同目录下的一个文件），每行一条“工作台名、终端类型、宽、高、布局名”。
- 布局对所有 `-n` 工作台通用（我的决定）。
- 删除或重命名布局：直接删除或重命名文件。删掉的布局如果还被设备记录引用，默认项回退到“默认”。

## 9. 约束与已知事实

- 运行环境：Linux、tmux ≥ 3.2（用户机上是 3.5a）、bash、python3（cw 已依赖）、zsh（用户的交互 shell）。
- cw 现有的踩坑记录（`docs/pitfalls.md`）依然适用，尤其是：
  - `-t` 精确匹配要写 `=名字`；
  - `set-option -p` 要显式指定 `-t`；
  - flock 的 fd 不能被 tmux server、watcher、`exec` 继承（`9>&-`）；
  - zsh 不做单词分割；
  - 不能往 Agent View 发送文本。
- ① 的识别依赖 `@cw_role=left`，④ 依赖 `@cw_role=right`。`respawn-pane -k` 会保留 pane 选项，`join-pane`、`break-pane`、`swap-pane` 也要实测确认选项是否保留。
- ④ 的 shell 环境里写死了 `CW_DIRFILE` 路径，路径按会话名生成。本设计不改会话名，所以不受影响。
- watcher 每轮按 `@cw_role` 动态找 pane，挪动 pane 不需要重启 watcher（要实测确认 pane 移到别的位置后仍然能找到）。

## 10. 留给实现者决定的

- 布局文件格式、比例的精度、分隔线的计算方法；
- 列表的具体显示（是否画缩略示意图）；
- §7.4 的匹配细节和移动 pane 的具体顺序；
- “保留”窗口的命名和创建时机；
- 窗口过小时的退化策略；
- 代码组织：继续在 `cw` 里写 shell，还是把布局计算放进一个 python 辅助脚本（建议后者，布局串解析、生成和校验和在 python 里更稳）。

## 11. 验收

- 在用户当前 316×72 的六格布局上执行 `cw -s`，存下来后 `cw -k`，再 `cw` 选择该布局：六格结构和比例还原；`top`、`npm exec @deepseek-ai/dsh@next web` 填在对应 pane 的命令行里**未执行**；附加 pane 在 `~`。
- 同一个布局在较小的终端（如 200×50）上套用时，比例与原布局一致，不出现只剩 1、2 行的 pane。
- 工作台运行中切到另一个布局：所有原 pane 进程仍在（在新布局里或在“保留”窗口）；① 未重启；④ 继续跟随目录。
- 工作台运行中从另一台尺寸不同的设备执行 `cw`，回车选当前布局：只有比例被修正，pane 没有被挪动，命令行里没有被重新填命令。
- 选“保持现状，直接进入”：工作台没有任何变化。
- 手动多拆了一个 pane 后执行 `cw` 并回车选当前布局：不调整，给出提示。
- 从 iTerm2 外接屏、iTerm2 笔记本屏、Windows Terminal 各选一次不同布局后，下次在各自设备上 `cw`，列表默认项分别是各自上次的布局。
- 没有保存任何布局时，`cw` 的行为与现在一致。
- `cw -i` 输出状态；README、`-h`、`install.sh` 提示已更新。
